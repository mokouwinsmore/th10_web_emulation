# 移植核对记录

对象是项目目录内的风神录日文 1.00a 与现成简体汉化版。浏览器执行各自原始程序和资源，关卡、弹幕、判定、计分、解锁和回放流程由原版代码决定。

## 已完成的核对

- 日文版连续运行六关，进入原版 Ending No.01，累计超过十万帧。自动长测使用测试脚本补充残机和火力以覆盖后期流程；这些辅助逻辑不在游玩包中。
- 另在即时编译执行下连续运行日文六关并进入结局，共 110,000 帧，未遇到运行错误。
- 六种自机、Easy / Normal / Hard / Lunatic 均有实际关卡运行；Extra 使用正确的第七关 STD、ANM、ECL，运行 24,000 帧并完成战斗。
- 两种语言的标题、选人、游戏、对话、灵击、暂停与返回。简体 Music Room 切换全部 18 首曲目及说明。
- 简体版从第六关运行到结局末页，累计 65,000 帧，实际显示中文 Ending No.01 和通关祝贺文字；原生离屏截图和完整文本均已保存。
- 原版生成录像文件，然后重新播放；录制与回放均得到 17,620 分、残机 -1。另将原版自带录像导入浏览器，成功从 Replay 菜单选择关卡并播放。
- 原版退出写入 score 和配置；浏览器持久保存、导出 JSON 备份、导入原版录像、恢复备份和重新启动。
- 在带中文、空格和方括号的独立解压目录运行；程序、资源、DLL、完整音乐均通过哈希校验。包内 Node.js 的签名仍有效，在系统 PATH 不含 Node.js 的情况下，启动脚本能够启动并复用已运行的服务。
- 独立解压包的两种语言均通过全屏、游戏、暂停、音频和退出保存测试；加载期间立即退出也能完成原版保存流程。通过虚拟手柄验证原版设备枚举、菜单确认、左右移动和射击输入。
- 37 个原版音效进入 DirectSound 后的 PCM 字节、声道数、位深和采样率全部与原始 WAV 一致。音乐分块不转码，完整音轨 SHA-256 记录在 manifest.json。
- 日文字体 MS Gothic 和简体字体 SimHei，各 15 个实际使用字号，对照本机 GDI 的颜色混合、裁剪和字形。CP932 / CP936 截断及非法字节序列也与 Windows 的输出对照。
- LZSS 解压与独立 Unicorn 执行的原版 x86 结果逐字节比较，包括重叠复制、字典保留与环回。
- D3DX 使用的 CRT double 返回值与调用栈核对。1.0.1 的 `npm test` 共 11 项测试全部通过。

## 画面精度

使用同一组游戏绘图指令、纹理和矩阵，分别在 Windows Direct3D 9 和浏览器 WebGL 2 绘制 640×480 图像。修复了 AlphaTest 的比较方式和 D16 深度量化；15 个深度边界样例与 8 个 AlphaTest 样例均一致。

抽取的标题、菜单、暂停与第一关画面，RGB 像素完全一致。另两帧中，灵击有 53 个颜色通道相差 1/255；恢复游戏画面有 42 个通道不同，最大相差 3/255。结果保存于开发目录 `artifacts/browser-quality-chs/pixels/rerender/result.json`。

这些是已测场景的结果，不能据此承诺所有显卡、浏览器、所有帧的像素与声音采样绝对相同。浏览器音频输出设备可能重采样；重负载或首次编译时，实际帧率也受电脑性能影响。

## 性能核对

减少接口读参的临时分配，渲染状态改为写入时复制，并将重复模型的原版矩阵、颜色和透明度按原有顺序合并提交。没有改动游戏更新次数、敌弹数量或判定。

在本机 i3-12100、启用硬件加速的 Chromium 中，第六关测试到第 2,850 帧时，实际绘制提交从 306,838 次降至 65,625 次；原始游戏仍发出相同数量的绘制命令。第 1,200 帧后的平均速度为 58.46 FPS，后段采样主要为 59.6～60.1 FPS。首次编译及系统调度仍可能造成短时波动，不能保证所有电脑始终保持 60 FPS。

## 1.0.1 文字加载修复

1.0.1 修复了 Music Room 和对话文字生成的性能问题。首次使用默认字号时，原先会读取、解压并解析完整字库；简体 32 号字库解压后的 JSON 约 26 MB。此外，文字缩放会产生约 5.5 万次跨越模拟器与 JavaScript 的取整调用，并逐像素进行浮点运算、格式转换及透明边缘处理。

现在将默认字库和文字转换代码的准备放在初始加载阶段；取整在 x86 中完成，原始 DLL 的缩放系数缓存后复用，浮点行运算、ARGB4444 转换及透明边缘处理使用逐字节核对的加速路径。字体仍使用原始 GDI 字形，文字贴图保持 16 位精度，GPU 上传复用原有存储。未覆盖的颜色键、伽马、抖动和异常浮点路径继续交给原始 DLL。

新增核对包括原始程序两种语言的透明边缘指令、D3DX 缩放及缓存、每个量化边界两侧的浮点值、CRT 调用栈与舍入模式，以及初始化过程对活动栈、CPU 上下文、游戏时钟和存档的保持。另有 16 组 GPU 上传对照，包含全部 65,536 种 ARGB4444 像素；结果完全相同。既有六个完整画面的原生 Direct3D 对照差异也没有扩大。

在同一台机器的简体新存档测试中，首次进入 Music Room 的 300 帧平均速度由约 37.3 FPS 提升至约 60.0 FPS，最长单帧由 691.8 ms 降至 82.6 ms；再次进入的平均速度由约 36.0 FPS 提升至约 58.4 FPS。记录位于开发目录 `artifacts/text-before-chs-music` 与 `artifacts/text-release-chs-music`。这些测量包含加载过程，浏览器编译和系统调度仍可能造成少量瞬时波动。

简体第一关的首次对话生成帧由 701.1 ms 降至 85.7 ms，后续七次实际台词切换由 198.8～344.3 ms 降至 29.5～43.6 ms。以发生 TextOutA 后的呈现帧统计，排除了测试脚本读取状态和保存截图造成的停顿。完整对话段平均约 59.8 FPS；记录位于 `artifacts/text-1.0.1-chs-dialogue`。

日文版另使用测试存档切换全部 18 首音乐，再次进入 Music Room，并实际运行第一关对话及八次推进，均通过。首次进入、全部曲目切换和再次进入的平均速度均约 60 FPS，实际对话文字生成帧为 27.7～40.2 ms。日文、简体对话截图均已检查；记录位于 `artifacts/text-1.0.1-jp-full`。测试存档不包含在游玩包内。

## 游玩包

游玩包只包含 dist、启动脚本、HTTP 服务、Node.js 和说明文档。不会包含原生诊断 EXE、测试辅助脚本、node_modules 或用户个人存档。Node.js 的 OpenJS Foundation 数字签名已核验有效。

原始游戏目录、已有永夜抄和妖妖梦移植项目均保留。风神录默认使用 8090 端口。
